# NAY-App v1 — Piano esecutivo

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** una web app offline per Android (Samsung) con Dashboard, Ideare, Sviluppare e Pubblicazioni salvate, protetta da password, con i dati cifrati nel telefono.

**Architecture:** PWA a file statici (JavaScript puro, moduli ES, nessuna build) servita da GitHub Pages. La logica sta in moduli puri provati con `node --test`; i dati stanno in IndexedDB, cifrati con AES-GCM da una chiave dei dati custodita due volte (password e codice di recupero); l'interfaccia sta in `js/ui/` e usa solo i moduli di `js/core/` e `js/features/`.

**Tech Stack:** HTML, CSS, JS (moduli ES), IndexedDB, WebCrypto, Service Worker. fflate 0.8.3 (MIT) per lo ZIP, snowball-stem 1.1.1 (BSD-3-Clause) per le radici delle parole, grafici in SVG scritti a mano. Test: `node:test` (Node 22) con fake-indexeddb 6.2.8 (Apache-2.0). Icone: Python 3 con Pillow.

**Spec:** `docs/superpowers/specs/2026-11-16-nay-app-design-v1.md` (approvato da Luca il 16 novembre 2026). Chi esegue legge anche la spec: qui ci sono solo le decisioni che la spec non prende.

## Global Constraints

- v1 solo Android (Samsung), tutto offline; iPhone e desktop dopo.
- JavaScript puro, file statici, senza passaggio di build e senza CDN: ogni libreria sta in `vendor/`.
- Nessun email, nessun account cloud, nessun segreto nel codice; repo pubblico.
- Una sola password, senza nome utente. PBKDF2 con SHA-256 e almeno 600.000 ripetizioni; AES-GCM; codice di recupero mostrato una sola volta.
- Lingue: spagnolo (predefinita) e italiano. Ogni idea, prompt e post ha un campo `lang`; i confronti avvengono solo tra testi della stessa lingua. Nessuna stringa di interfaccia fuori da `js/i18n/`.
- Bandierine come immagini (non emoji) in alto a destra, con sigla ES e IT; lingua salvata in chiaro nel telefono.
- Barra in alto: logo NAY su tessera crema a sinistra con accanto il numero di versione (`APP_VERSION`), titolo, bandierine e menu ⋮ a destra. Barra in basso con 4 icone: Dashboard, Ideare, Sviluppare, Pubblicazioni.
- Condivisione di sistema: ZIP, JSON e backup non si condividono, si salvano nel telefono. Copia e condivisione solo da un tocco dell'utente, in HTTPS.
- Avviso sui file quando sono più di 10 (limite di Gemini).
- Look del poster: sfondi `#000104`, `#02061a`, `#080921`, `#081937`; ciano `#26a4c5`, `#2381ac`; magenta-viola `#b458bc`, `#ad429e`; blu-viola `#495ec6`, `#613bab`. Una colonna.
- Il file `LICENSE` non si crea finché Luca non sceglie la licenza (dopo il test sul Samsung).
- Niente dati inventati: ciò che non è verificato va marcato **[Da provare]** nei documenti.

## Review Focus

1. Password o testi con accenti, ñ, ¿ ¡ digitati con tastiere diverse (NFC contro NFD): la password deve aprire sempre il vault, e «Ánimo» deve trovare «animo». Test in T4 e T7.
2. Primo avvio interrotto prima di confermare il codice di recupero: al riavvio la creazione riparte e non resta un vault a metà. Test in T4, verifica manuale in T11.
3. File di backup troncato, di un'altra versione o aperto con la password sbagliata: errore chiaro e dati attuali intatti. Test in T9.
4. Memoria piena (`QuotaExceededError`) mentre si salva una foto o un video: messaggio all'utente e nessun record a metà. Test in T5.
5. Dopo un aggiornamento su GitHub Pages il telefono continua a servire la versione vecchia dalla cache: il numero di versione accanto al logo mostra quale gira, e la cache cambia nome a ogni versione. Test in T11.
